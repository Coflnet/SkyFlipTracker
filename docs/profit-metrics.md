# Private tracked auction profit

Set `ProfitMetrics:Enabled=true`, `ProfitMetrics:Port=9092` and `ProfitMetrics:CoverageStartUtc` to an explicit future UTC midnight **after every writer has this version enabled**. Before that coverage boundary no total is claimed. A restart or new replica must use the same boundary. The feature defaults off. Normal public application routes and the existing public Prometheus registry never expose these business metrics.

`ProfitMetricProjection` receives the same corrected `PastFlip.Profit` which `FlipStorageService` persists, including cost/tax changes and negative outcomes. Unknown/uncertain cost outcomes contribute zero; no money is recomputed from purchase/sale prices or the gross Kafka summary event. Projection identity is the sell auction ID (purchase ID for an empty sell ID), so resaves and corrections replace contributions. A registry detects day/owner identity changes and preserves the authoritative source write while marking both days incomplete; these require explicit reconciliation rather than an invented total.

The per-sale registry CAS allocates a shared monotonic write timestamp across replicas, including when their wall clocks coincide. The source and contribution use that same explicit timestamp in a logged batch, with the next microsecond reserved for the pending tombstone. The contribution and deletion of its durable pending marker occupy the same partition. A failed or interrupted write therefore either retries idempotently or leaves that day incomplete. Existing consumers must continue acknowledging only successful writes. A future writer which bypasses `SaveFlip`/`SaveFlips` must also participate before extending the coverage claim. Existing history is not backfilled by scanning the player-partitioned source.

The exporter reads at most `ProfitMetrics:MaximumRowsPerDay` projection rows (default 100,000, configurable up to 1,000,000) across 32 partitions per UTC day, then caches the anonymous result for five minutes. `ProfitMetrics:LookbackDays` defaults to eight (bounded 2–8), covering today and the previous seven days. It never scans all historical flips. Exceeding the bound, a pending write, stale/unloaded opt-out state, unknown coverage, numeric overflow or insufficient integer precision suppresses the affected day's profit value. If observed throughput exceeds the reviewed bound, add a reviewed summary/reconciliation strategy before raising it; incomplete is safer than an unbounded query. The collector must republish the same lookback with fresh revision timestamps, so closed days include their final minutes and later corrections. Corrections beyond the lookback and initial-history reconciliation require explicit historical export.

Privacy erasure first records permanent owner suppression, then erases the source and reverse-indexed projection rows. A failure can retry while aggregates exclude the owner. A concurrent writer which passed its local opt-out check cannot reintroduce their contribution. The exporter also checks the existing opt-out snapshot and requires a successful refresh within two hours. The suppression table contains only the player UUID necessary to prevent resurrection; business metrics contain no player identifiers.

Only the private listener serves `sky_fliptracker_realized_profit_coins{day}`, `sky_fliptracker_profit_complete{day}`, `sky_fliptracker_profit_snapshot_timestamp_seconds{day}` and the coverage-start timestamp. Wire a ClusterIP Service, monitoring-only port policy and ServiceMonitor without adding public routing. The private collector must select the freshest replica, never sum replicas, and must validate the source-computation timestamp. No authoritative total-registered-user metric exists in this change. Connected premium users are a different measure.

Run `scripts/cassandra-smoke.sh` after restoring packages. It uses the existing pinned disposable Cassandra lifecycle and runs the original storage mapping test plus the profit projection test. The latter covers duplicate writes, corrected values/losses, uncertain cost flags, failed source writes and retry recovery, privacy deletion failures and resurrection attempts, independent replicas issuing revisions at the same wall-clock time, concurrent correction ordering, closed-day corrections, cross-midnight fail-closed behavior, private/public listener separation and bounded scans. `CASSANDRA_SMOKE_EXTRA_PROJECT` may name an independent C# executable to run against the same disposable instance, for example Tod's collector conditional-write tests. The script never connects these tests to a production database.
